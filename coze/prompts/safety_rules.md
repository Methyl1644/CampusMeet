# 安全规则（Safety Rules）

> 适用于全部工作流的安全与风险判断提示词片段，与后端 `src/utils/security.py` 规则引擎保持一致。
> **层级关系**：后端规则引擎是最终拦截层；Coze 工作流只做识别、解释和建议，不替代后端规则（PRD §5.4、user-flow §3 阶段四）。

---

## 1. 敏感信息检测（与后端规则引擎一致）

| 类型 | 说明 | 处理 |
|------|------|------|
| 身份证号 | 18 位身份证号（含 X） | 标记 `blocked_fields`，必须脱敏 |
| 手机号 | 1 开头 11 位数字 | 标记并脱敏，公开帖禁止出现 |
| 微信号 | "微信/vx/WeChat"+账号 | 标记并脱敏，确认成队前禁止交换 |
| QQ 号 | "QQ/qQ"+5-11 位数字 | 标记并脱敏 |
| 精确住址 | 楼栋号、门牌号、宿舍房间号 | 标记并脱敏，只保留校区级地点 |
| 违禁词 | 后端违禁词表命中的词 | 标记并升级风险 |

脱敏统一用 `***` 掩码，输出到 `sanitized_text`。

## 2. 违规内容（直接高风险）

以下场景 `risk_level = high`，`audit_result` 建议 `manual_review` 或 `reject`：

- **代写/作弊**：代写作业、代考、代写论文、买卖答案
- **金钱交易**：押金、收费入队、借贷、垫付
- **票务倒卖**：倒卖演出票、车票、球鞋等
- **诈骗诱导**：刷单、兼职返利、引导站外交易
- **诱导线下高风险**：约见陌生地点、夜间单独见面、诱导离开平台监管

## 3. 优先支持的场景（正常不误杀）

比赛（美赛、挑战杯等）、科研、课程项目、学习搭子等学业场景，无敏感信息时 `risk_level = low`，`audit_result = approve`。

## 4. 风险升级因素（升至 medium）

| 因素 | 示例 |
|------|------|
| 线下活动 | 约球、线下讨论（标注地点建议选公共场所） |
| 夜间 | 22 点后活动 |
| 金钱 | AA 制拼团（提示平台不担保交易） |
| 长途 | 跨城市出行 |
| 旅行/户外 | 登山、露营等 |

medium 等级给出风险提示但可发布，`audit_result = approve` 或 `modify`，`needs_manual_review = false`。

## 5. 误杀防护

- 正常内容不得误判：如"我微信名也叫这个"类上下文需结合语义判断；拿不准时 `needs_manual_review = true`，交由人工，不直接 reject。
- 被拦截内容必须给出**修改建议**（`suggested_revision`），告诉用户怎么改能通过，例如"请删除手机号，联系方式将在双向确认成队后自动解锁"。

## 6. 发送给 Coze 的数据边界（PRD §5.3）

后端调用任何工作流前必须剔除：

1. 密码（任何形态）
2. 原始身份证、学生证照片及其 OCR 文本
3. 原始邮箱/手机验证码
4. 原始认证材料
5. 未脱敏的联系方式（手机号、微信、QQ），除非业务确实需要且用户已授权

工作流输入中若仍出现上述内容，按第 1 节标记脱敏，并在 `reviewer_note` 中记录"输入疑似含未脱敏敏感信息"。
