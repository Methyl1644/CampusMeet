# 工作流④ Prompt：成队规划（team_plan）

> 前置：先拼接 `system_rules.md` + `safety_rules.md`，再接本 Prompt。
> 输出 Schema：`coze/schemas/team_plan.output.json`
> 核心原则：**只建议，不决定**。所有分工、任务都是建议，成员可自行调整。

---

## 任务

双向确认成队后，生成：建议分工、第一次会议议程、第一周任务清单、里程碑、风险提醒。

## 输入变量

- `{{team_info}}` / `{{activity_info}}`：团队与活动信息
- `{{members}}`：成员列表
- `{{deadline}}`：最近关键截止日期
- `{{member_skills}}` / `{{member_availability}}`：成员技能与每周可投入时间

## 处理步骤

1. **建议分工** `role_assignments`：
   - 每名成员一个建议角色，依据 `member_skills` 中最贴合活动需要的技能，`reason` 必须引用该成员的实际技能；
   - 覆盖活动所需的关键职能；没人能覆盖的职能写入 `missing_roles`，并提示"可考虑继续招募或由成员兼任"；
   - 工作量分配参考 `member_availability`，时间少的成员不压重任务。
2. **第一次会议议程** `first_meeting_agenda`（4-6 项，按此骨架裁剪）：
   确认活动目标与期望 → 确认分工 → 确认时间表与固定沟通机制 → 确认最近截止事项 → 自由讨论。每项给建议时长。
3. **第一周任务** `first_week_tasks`（3-6 条）：
   每条有 `task`、`owner_id`、`due`。任务要具体可执行（"完成报名信息整理"而不是"准备一下"），`due` 在第一周内且早于 `deadline`；负责人与分工一致。
4. **里程碑** `milestones`：从当前到活动结束 3-5 个关键节点（报名、初稿、提交等），日期与 `activity_info` 一致。
5. **风险提醒** `risk_reminders`：至少包含：最近截止日期确认提醒；投入时间明显不足的成员（若有）；`missing_roles` 非空时的能力缺口提醒。
6. **下一步行动** `next_actions`：2-4 条按优先级排序的建议（如"先召开第一次线上会议确认分工与时间表"）。

## 约束

- 不编造活动规则、报名链接、比赛日期；输入没有的信息在 `risk_reminders` 中提示"需核实"。
- 称谓使用昵称，不出现联系方式。
- 语气是"建议"而非"指令"：议程、任务均可调整。

## 示例

输入：小王（Python、数学建模，10h/周）、小李（英语写作、论文排版，6h/周）、小张（Python、算法，8h/周）组成美赛队，报名截止 2026-08-15，比赛 2026-09。

输出要点：
- `role_assignments`：小王→建模与代码（Python+数学建模）；小李→论文写作与排版（英语写作+论文排版）；小张→编程实现与数据处理（Python+算法）
- `first_meeting_agenda`：确认冲奖目标(10min) → 确认分工(15min) → 确认每周时间表与例会(15min) → 确认报名截止事项(10min)
- `first_week_tasks`：完成报名信息整理（小王，08-15 前）；收集历年真题与优秀论文（小李，08-18）；搭建代码环境与 Git 仓库（小张，08-18）
- `risk_reminders`：["报名截止 2026-08-15 需要再次确认并提前完成", "小李每周 6h 低于备赛强度，建议沟通是否能阶段性增加投入"]
