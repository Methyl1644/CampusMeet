# CampusMate 南京大学校园主题前端重构设计

日期：2026-09-10

## 1. 目标

在不改变现有路由、权限、接口与数据结构的前提下，将 `apps/web` 从通用 Tailwind 演示界面重构为具有南京大学校园识别度的正式产品界面。

设计采用“校园刊物式操作界面”：官方话题具有公告与档案感，学生组队帖保持轻量和亲切，搜索、申请、消息及 AI 发帖仍以高效率完成任务为首要目标。

## 2. 范围与边界

本轮覆盖以下现有页面和通用组件：

- 登录与注册 `/login`
- 首页和发现页 `/home`、`/discover`
- 话题详情 `/topics/:id`
- 组队帖详情 `/posts/:id`
- AI 发帖 `/publish`
- 消息 `/messages`
- 成队页 `/teams/:id`
- 个人中心 `/profile`
- 顶部导航、手机底部导航、卡片、按钮、输入框、徽章、Toast、加载与空状态

本轮明确不改变：

- URL、路由结构与登录拦截逻辑
- API 请求路径、请求字段和响应字段
- 话题、组队帖、标签库、AI 草稿与认证权限的业务规则
- 后端、数据库和 Coze 工作流
- 产品文档中的核心中文业务名称

## 3. 视觉方向

### 3.1 设计语言

整体参考南京大学校刊、校园公告与建筑材料的组合，而不是复制学校官网。视觉识别由以下元素形成：

- 南大紫作为品牌色和主操作色
- 墨绿用于官方认证、安全提示和成功状态
- 暖白作为主要页面背景，深墨色作为正文颜色
- 校钟楼圆章作为品牌图形，在导航、登录页和官方话题中节制使用
- 细线、栏目标题、编辑式留白和明确的文字层级形成校刊气质
- 不使用装饰性紫色光球、满页渐变、悬浮卡片墙或营销型 Hero

### 3.2 色彩令牌

| 用途 | 建议色值 |
| --- | --- |
| 主品牌紫 | `#5B2A86` |
| 深紫 | `#3E1A5F` |
| 浅紫底 | `#F1EAF6` |
| 认证墨绿 | `#175C4A` |
| 提示金 | `#B17A24` |
| 暖白背景 | `#F7F5F1` |
| 纸白 | `#FFFEFC` |
| 正文墨色 | `#211D24` |
| 次要文字 | `#6F6873` |
| 边框石灰 | `#DDD7DF` |

紫色保持主导，但认证、风险、错误等语义状态使用独立颜色，不能仅靠深浅紫表达所有状态。

### 3.3 字体

- 标题：开源中文宋体，优先 `Noto Serif SC`
- 正文和界面：开源中文黑体，优先 `Noto Sans SC`
- 数字和英文跟随正文，但使用等宽数字特性以减少计数变化导致的跳动
- 字体作为前端依赖随构建产物提供，不依赖用户系统字体或外部 CDN

## 4. 信息架构与页面层级

### 4.1 导航

桌面端保持一行顶部导航。左侧为钟楼图形与 CampusMate，中央为首页、发现、发布、消息、我的，右侧显示用户和退出操作。当前页面使用紫色下划线和文字强调，不使用大面积胶囊导航。

手机端保留五项底部导航。发布使用中心主操作图标，但尺寸受控，不遮挡内容。底部导航考虑安全区域 `env(safe-area-inset-bottom)`。

### 4.2 发现页

结构保持：页面引导区、三类频道、单一搜索框、已选标准标签、结果列表。

- 三类频道是最高级导航，切换时清空当前搜索和标签。
- 官方赛事与认证组织显示话题卡片，用户必须先进入话题再查看相关组队帖。
- 同学自主组队直接显示组队帖，不制造虚假的上层话题。
- 搜索建议中“话题直达”优先于标准标签，输入简称或关键词即可出现完整话题名。
- 选择标签后，标签显示在搜索框下方并带有明确的移除按钮。

### 4.3 卡片层级

官方话题卡片使用较强图像区、来源标记、完整标题、摘要、主办方、关注数与组队入口。卡片视觉上比组队帖更稳定、正式。

组队帖卡片聚焦活动名、所需角色、时间、人数、发起者与状态。减少无关说明，使用户能快速比较。

卡片圆角统一为 8px。列表项内部不再嵌套第二层卡片。

### 4.4 详情页

话题详情先展示活动身份、标题、摘要、标准标签、来源与关注操作，再展示活动资料和相关组队帖。发布组队入口在标题区和组队列表标题区各出现一次，移动端保留一个主要入口。

组队帖详情突出申请状态、所需角色、时间与风险。AI 匹配说明是辅助决策信息，不能比组队基本条件更抢眼。

### 4.5 登录与注册

登录页使用钟楼照片或圆章作为校园识别面，表单保持单一焦点。登录和注册使用分段控件切换。

登录成功直接进入站内。注册阶段使用表单底部横向进度线，阶段之间使用淡入和轻微水平移动。开发环境的演示入口保持低调，并明确说明其用途。

### 4.6 AI 发帖

桌面端采用对话区与结构化草稿双栏。草稿区更像编辑批注栏，字段状态、标准标签和发布条件一眼可见。手机端草稿使用底部可展开区域，避免压缩对话空间。

AI 思考、回复到达、标签加入与草稿更新需要反馈动画。AI 不可用时的手动模式必须保持完整可用。

## 5. 动效规范

动效强度设为 5/10，强调反馈与方向感。

| 场景 | 动效 | 时长 |
| --- | --- | --- |
| 页面进入 | 淡入并上移 8px | 260ms |
| 频道切换 | 指示线平移，结果轻微交叉淡化 | 220ms |
| 搜索建议 | 缩放 `0.98` 到 `1` 并淡入 | 160ms |
| 卡片列表 | 小幅依次进入，单项间隔不超过 35ms | 240ms |
| 按钮点击 | 轻微压缩并恢复 | 120ms |
| 关注状态 | 图标填充和计数淡化切换 | 180ms |
| 登录注册阶段 | 左右方向切换并淡入 | 220ms |
| AI 消息 | 新消息上移进入 | 180ms |
| Toast | 右上或底部滑入，退出淡化 | 200ms |

不得使用持续漂浮、无限旋转、视差滚动、自动横向跑马灯或阻碍阅读的入场动画。所有动画在 `prefers-reduced-motion: reduce` 下禁用位移和缩放，只保留即时状态变化。

## 6. 组件与实现策略

### 6.1 设计令牌

在 Tailwind 配置和 `index.css` 中统一定义品牌色、字体、圆角、阴影、焦点环和动画。现有 `primary-*` 映射到南京大学紫，减少页面级重复替换。

### 6.2 动效实现

优先使用 Motion for React 管理页面、列表和状态过渡，CSS 负责 hover、focus、加载骨架与减少动画设置。动画组件保持为小型叶子组件，不把业务请求状态移入动画层。

### 6.3 图标与图像

- 继续使用现有 `lucide-react`，不手绘 SVG 图标
- 使用现有钟楼圆章作为核心校园资产
- 官方话题允许使用真实活动图片；缺图时使用统一的校园纸纹与钟楼占位，不反复拉伸同一照片
- 所有信息性图片提供准确替代文本，装饰图像使用空替代文本

### 6.4 可访问性

- 键盘焦点始终可见
- 正文和主要按钮达到 WCAG AA 对比度
- 状态不只依赖颜色，同时使用图标或文字
- 搜索建议保留可读标签和按钮语义
- 图标按钮具有 `aria-label` 和悬停提示
- 动态内容使用适当的 `aria-live`，避免重复播报

## 7. 响应式规则

- 桌面内容最大宽度维持 1200px
- 768px 以下切换到底部导航和单列内容
- 话题卡片在小屏上使用上方横幅图加正文，不保持过窄的左右分栏
- 登录页在手机端只显示表单与小型校园标识，隐藏大幅视觉面
- AI 发帖、消息与成队页使用 `100dvh` 计算可用高度
- 固定导航、输入区和弹层不能互相遮挡

## 8. 状态与异常

每个核心列表和表单都需要保留加载、空、错误和禁用状态。动效不能隐藏错误，也不能造成提交两次。接口失败时继续使用现有 Toast 和降级逻辑。

图像加载失败时回退到品牌占位。字体加载失败时回退到系统中文字体，页面尺寸不能明显跳动。

## 9. 验证标准

### 自动验证

- `pnpm lint`
- `pnpm build`
- 现有前端测试全部通过
- TypeScript 无类型错误

### 浏览器验证

- 1440 x 900 桌面视口
- 390 x 844 手机视口
- 登录、三频道切换、搜索建议、标签增删、话题详情、发布页和消息页可操作
- 页面无水平溢出、文本截断错误、遮挡和明显布局跳动
- 浏览器控制台无错误
- 在减少动态效果模式下验证内容仍完整可用

### 视觉完成标准

- 首屏能在不依赖文字说明的情况下识别校园主题
- 紫色是品牌主色，但页面不呈现单一紫色调
- 官方话题与普通组队帖具有清晰的视觉优先级差异
- 动效能够解释为层级、反馈或状态过渡，不存在纯装饰动画
- 页面不使用默认浏览器字体
