# CampusMate Meetup 风格产品重设计

## 1. 目标与范围

本次改造将 CampusMate 从“内容列表 + 发布 + 组队”的功能集合，升级为具有完整新用户路径、个性化首页、活动探索、组队参与、消息通知和个人资料展示的校园活动平台。

设计参考 Meetup 的信息层级、留白、卡片比例、导航位置、分步表单和短促转场，但不复制其品牌资产、文案或商业功能。CampusMate 保留中文校园语境、南京大学范围、紫色主品牌色和已有审核治理体系。

本次范围包含：

- 简化登录和注册，新增首次资料完善向导。
- 重建全站导航、首页、探索页、活动详情、组队详情、消息、通知、个人主页、设置、教程和页脚。
- 将现有三频道在用户界面中聚合为“活动”和“组队”。
- 增加收藏、参加、加入、首页推荐、截止提醒及公开资料所需的数据和接口。
- 保留现有标签、审核、权限、申请、私信和队伍协作能力。

暂不包含：

- 网站标志定稿。
- 第一阶段对现有发布页的视觉重做。
- 付费、票务、跨校位置搜索和第三方地图服务。

## 2. 产品语言与内容模型

### 2.1 用户可见分类

探索页只显示两个一级分类：

- **活动**：正式、有明确安排且准备充分的活动，包括国家级、省级、校级、院系或书院活动。它聚合现有 `official` 和 `organization` 频道的 `Topic`。
- **组队**：学生发起的临时、小规模、相对随意的活动或招募。它以现有 `Post` 为内容入口，以申请和 `Team` 表示加入后的协作关系。

原有三频道继续作为后端治理维度存在，不再作为普通用户的一级导航。这样无需破坏现有发布权限、组织认证和内容审核逻辑。

### 2.2 活动参与方式

每个活动增加 `participation_mode`：

- `open_team`：允许用户围绕活动发布多个招募队友帖。
- `official_signup`：只允许活动管理者创建一个官方高容量报名帖。
- `information_only`：只展示信息，不开放站内报名或组队。

活动关联帖子增加 `purpose`：

- `team_recruitment`：围绕正式活动招募队友。
- `official_signup`：官方统一报名入口。
- `discussion`：经验请教、信息交流，不代表报名或正式队伍。

数据库和服务层必须保证：同一 `official_signup` 活动最多只有一个有效官方报名帖；普通用户不能创建该用途帖子；讨论帖可以出现在“组队”探索中，但必须明确标注“讨论”。

## 3. 账号与首次引导

### 3.1 登录与注册

- 登录只保留南京大学邮箱和密码，不再展示或发送登录验证码。
- 忘记密码继续使用注册邮箱验证码。
- 注册保留校园邮箱验证码，只收集邮箱、验证码和密码。
- 注册成功后直接签发登录状态，并进入首次资料完善向导。
- 后端为新用户生成临时昵称，但该昵称不会作为完成资料的依据。

### 3.2 六步资料向导

向导采用录屏中 Meetup 创建流程的结构：顶部六段进度，左侧单一任务，右侧简短提示，底部一个明确主操作。

1. **头像与称呼**：昵称必填，头像可跳过。
2. **校园身份**：院系/专业和年级必填。
3. **兴趣方向**：至少选择三个标准标签，可搜索和展开更多。
4. **参与目的**：比赛组队、学习交流、兴趣社交、志愿活动、寻找长期伙伴等，可多选。
5. **能力与时间**：技能、常用空闲时段、每周可投入时间，均可跳过。
6. **资料预览**：简介、联系方式可见性和公开资料预览，确认后完成。

每一步保存后端草稿。刷新、退出或设备切换后从最近步骤恢复。未完成必填资料的账号访问业务路由时统一跳转向导；设置页可以在之后修改所有字段。

### 3.3 动效规范

- 前进：内容从右侧 `16px` 淡入，旧内容向左 `10px` 淡出。
- 返回：方向反转。
- 页面转场时长 `180-240ms`，使用平缓减速曲线。
- 进度段先更新颜色，再完成内容替换；右侧提示与内容同步淡入。
- 兴趣标签选择使用颜色填充和轻微缩放反馈，不移动周围布局。
- 支持 `prefers-reduced-motion`，关闭位移动画，仅保留即时或短淡入。

## 4. 全站框架

### 4.1 桌面导航

顶栏从左到右为：待定标志、首页、探索、发布、弹性留白、消息、通知、教程、用户头像与下拉箭头。

- 顶栏保持白色或近白色，底部使用细分隔线，不使用大面积紫色背景。
- 当前栏目通过深色文字和短下划线或轻背景强调。
- 消息和通知使用图标按钮及未读圆点；教程使用问号图标。
- 用户菜单包括：我的活动、我的小组、查看个人主页、设置、退出登录。
- 移动端使用底部五栏：首页、探索、发布、消息、我的；通知和教程进入“我的”页面顶部。

### 4.2 视觉系统

- 页面背景使用接近 Meetup 的冷白色，内容区使用纯白，不采用整页米黄色。
- 主文字为接近黑色；次文字为中性灰；紫色仅用于选中、链接、进度和主要操作。
- 卡片圆角控制在 `8px`，活动封面可使用较大圆角但不超过 `12px`。
- 卡片以图片、标题、日期、组织者、参与人数为主要扫描顺序，减少边框和阴影。
- 页面标题粗体、紧凑；正文保持舒适行高；中文界面不模仿英文文案宽度。
- 动画只服务于状态变化、横向浏览、菜单展开和页面切换，不添加装饰性漂浮元素。

## 5. 首页

桌面首页采用左侧摘要栏和右侧主内容双栏布局。

左侧固定宽度摘要区：

- 用户头像、昵称、院系/年级和进入个人主页入口。
- “我的活动”模块，含“参加中/已收藏”切换、最近一项及“查看全部”。
- “我的小组”模块，显示最近加入的队伍和“查看全部”。

右侧主内容：

- 最上方显示一个可关闭的截止提醒横幅。没有临近截止内容时不占位。
- “为你推荐”横向活动列表，根据兴趣标签、专业、收藏及参与历史排序。
- “来自我的小组”按日期展示已加入队伍的近期活动或任务；无内容时显示克制的空状态和探索入口。
- 后续可增加“校园正在发生”，但不进入首轮实现。

移动端改为单栏：用户摘要压缩为顶部信息行，活动和小组摘要使用横向模块，推荐卡片横向滚动。

## 6. 探索页

### 6.1 页面层级

1. `活动 / 组队` 分段标签。
2. 随选中标签变化的粗体解释标题。
3. 搜索框，固定在标签和标题下方，不进入顶栏。
4. 日期、规模、类型、校区范围筛选。
5. 横向兴趣分类导航。
6. 卡片结果网格和分页/继续加载。

活动标题使用“发现值得认真准备的校园活动”，组队标题使用“找到此刻正缺你的队伍”。辅助文案解释正式活动和学生自发组队的边界。

### 6.2 卡片

活动卡片包含：封面、收藏按钮、状态或剩余名额、标题、日期时间、组织者、活动范围、参与人数。日期和截止状态优先于描述。

组队卡片包含：封面或稳定的分类占位图、用途标签、标题、活动时间/截止时间、发起人、当前人数与目标人数、所需角色。与正式活动关联时显示活动名称并可跳转。

切换活动/组队时，选中背景滑动 `200-240ms`，标题与结果轻微淡入；搜索和筛选值按分类分别保存，返回时恢复。

## 7. 详情、收藏与参与

### 7.1 活动详情

首屏左侧显示标题、组织者和活动身份，右侧显示封面；时间、地点、校区、人数上限集中在信息面板。正文下方依次为详情、地点信息、参与者预览和关联组队。

底部桌面端使用粘性操作栏，移动端使用安全区底栏：收藏、分享、报名或寻找队友。

关联组队区域：

- `open_team`：显示“发布组队”快捷入口及全部招募帖。
- `official_signup`：突出唯一官方报名帖，不显示普通组队入口。
- `information_only`：只显示说明和相关讨论。

发布页未重做前，详情页可以展示入口，但自动预填和自动继承标签在发布页专项阶段统一接通，避免两次改造同一表单。

### 7.2 我的活动与我的小组

- 我的活动包含“参加中、已收藏、已结束”三个视图。
- 我的小组包含“已加入、申请中、已收藏、已归档”四个视图。
- 首页“查看全部”直接进入对应视图。
- `TopicFollow` 继续表示活动收藏；新增 `PostBookmark` 表示组队收藏。
- 已接受申请并加入 `Team` 后才计入“已加入”。

## 8. 消息、通知、教程和个人资料

### 8.1 消息

复用现有会话接口，桌面端使用会话列表 + 对话双栏；移动端分为会话列表页和对话页。空状态提供“去探索组队”的入口。交换联系方式仍由双方确认后的现有机制控制。

### 8.2 通知

复用现有 `Notification` 模型和已读接口，新增前端通知页、未读计数和导航圆点。通知至少覆盖：发布成功、内容违规或隐藏、申请提交、申请结果、队伍成立、队伍变更、活动临近截止。

### 8.3 教程

教程按任务组织：如何区分活动与组队、如何围绕活动找队友、官方报名规则、讨论帖边界、申请与交换联系方式、举报与隐私。活动详情和发布入口提供对应章节的深链接。

### 8.4 个人资料与设置

新增公开个人主页路由，展示头像、昵称、院系年级、简介、兴趣、技能、参与方向及用户允许公开的活动/小组。设置页负责资料编辑、隐私、密码、通知偏好和账号管理。联系方式默认不公开。

## 9. 后端设计

### 9.1 数据变更

`users` 新增：

- `onboarding_step`
- `onboarding_completed_at`
- `bio`
- `interests` JSON
- `looking_for` JSON
- `availability` JSON
- `profile_visibility` JSON

`topics` 新增：

- `location_name`
- `campus_scope`
- `capacity`
- `participation_mode`

`posts` 新增：

- `cover_url`
- `purpose`
- `join_mode`

新增 `post_bookmarks`。不增加另一套活动参加记录：活动参加状态统一由 `TeamMember -> Team -> Post.topic_id` 推导，参加人数按用户去重。官方报名帖也使用同一队伍成员关系，只是采用直接加入模式。官方报名帖唯一性由针对有效 `official_signup` 帖子的数据库部分唯一索引和服务层校验共同保证。

### 9.2 接口变更

- 调整注册和登录请求结构，删除登录验证码分支。
- 增加引导草稿读取、分步保存和完成接口。
- 扩展个人资料与公开资料接口。
- 增加首页聚合接口，返回截止提醒、推荐、近期活动和小组动态。
- 增加我的活动、我的小组和组队收藏接口。
- 扩展活动和帖子列表的筛选、排序及卡片字段。
- 在服务层校验活动参与模式、帖子用途、官方报名唯一性和权限。
- 扩展通知事件创建点和目标链接。

推荐首版使用可解释的规则排序：兴趣标签重合度、时间接近度、校区匹配、收藏/参与历史和内容新鲜度。暂不引入新 AI 推荐服务。

## 10. 错误处理与兼容

- 所有新增数据库字段提供安全默认值，旧账号首次登录时根据关键资料完整度决定是否进入引导。
- 引导保存失败时保留本地输入并显示重试，不错误推进步骤。
- 首页聚合的某个分区失败不阻塞整页，其余分区正常展示。
- 收藏和加入操作使用幂等语义，重复请求不产生重复记录。
- 官方报名唯一性同时由数据库约束和服务层错误信息保证。
- 旧链接 `/topics/:id`、`/posts/:id`、`/profile` 保持可用，通过路由兼容进入新页面。
- 无封面的旧内容使用分类占位图，不在列表加载时发生布局跳动。

## 11. 实施分解

### 阶段一：账号和资料引导

完成数据库迁移、注册/登录契约、六步向导、路由守卫和旧账号兼容。这一阶段结束后，新用户能够从注册完整进入首页。

### 阶段二：全站框架和首页

完成导航、头像菜单、首页聚合接口、活动/小组摘要、截止提醒、推荐区、通知入口和响应式布局。

### 阶段三：探索和详情

完成活动/组队双分类、筛选、卡片、活动详情、组队详情、收藏、参加/加入状态及官方报名规则。

### 阶段四：个人区域和辅助页面

完成我的活动、我的小组、通知中心、公开个人主页、设置、教程和页脚；整合现有消息页面。

### 阶段五：发布页专项

在前四阶段通过后再重做发布页，接入活动快捷发布、活动标签自动继承、帖子用途选择和官方报名限制。

## 12. 验证标准

- 后端：迁移测试、注册/登录测试、引导恢复测试、收藏幂等测试、活动参与模式权限测试、官方报名唯一性测试、通知事件测试。
- 前端：路由守卫、六步向导、首页各状态、活动/组队切换、筛选恢复、收藏/加入、用户菜单和空/错/加载状态测试。
- 端到端：新用户注册到首页、旧用户登录、收藏活动、申请组队、查看通知、编辑公开资料。
- 视觉检查：桌面 `1440x900`、平板 `1024x768`、移动端 `390x844`；确认卡片比例、文字截断、粘性操作栏和菜单没有重叠。
- 动效检查：正常动画和减少动态效果两种模式；列表切换不导致页面宽度或高度异常跳动。
- 部署检查：前端构建、后端测试、Alembic 升级、Render API 健康检查和 Web 路由回退。

## 13. 完成定义

除发布页专项外，用户能够完成注册、首次资料引导、浏览个性化首页、探索活动和组队、查看详情、收藏与加入、收发消息、阅读通知、管理个人资料并理解活动参与规则。发布页专项完成后，活动详情到自动带标签组队帖的闭环才视为全部完成。
