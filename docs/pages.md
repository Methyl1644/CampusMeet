## 2. 通用规范

### 2.1 布局适配

| 端 | 布局 | 说明 |
|----|------|------|
| 桌面端（Windows） | 顶部导航 + 宽屏内容区 | 最大宽度 1200px 居中 |
| 手机端 | 底部 Tab 导航 + 单列内容 | PWA 适配 |

### 2.2 导航结构

**桌面端顶部导航**：
```
[Logo] 首页  发现  发布         消息  我的
```

**手机端底部导航**：
```
[首页]  [发现]  [+发布]  [消息]  [我的]
```

### 2.3 来源徽章样式

| 来源类型 | 徽章颜色 | 文案 |
|----------|---------|------|
| 官方来源 | 蓝色 | 官方 |
| 认证组织 | 绿色 | 认证组织 |
| 普通用户 | 灰色 | 无徽章或"个人" |

### 2.4 风险等级标签

| 风险等级 | 颜色 | 说明 |
|----------|------|------|
| low | 绿色 | 正常 |
| medium | 橙色 | 需注意（线下/夜间等） |
| high | 红色 | 高风险，需人工复核 |

## 3. 各页面详细定义

### 3.1 登录/注册页 `/login`

#### 页面要素

| 区域 | 内容 | 交互 |
|------|------|------|
| 顶部 | Logo + 标语"AI 赋能校园组队" | 静态展示 |
| 注册区 | 手机号/邮箱输入 + 验证码 | 输入后发送验证码 |
| 登录区 | 手机号/邮箱 + 密码/验证码 | 已有账号直接登录 |
| 认证入口 | "校园邮箱认证"按钮 | 登录后引导认证 |

#### 交互说明

1. 新用户先注册（手机号/邮箱 + 验证码），注册后引导填写基础资料
2. 基础资料：昵称、专业、年级、技能标签（多选）
3. 完成资料后引导校园邮箱认证
4. 未认证用户可浏览，但发帖和申请时提示"请先完成校内认证"

#### 验收标准

- [ ] 能通过手机号/邮箱完成注册
- [ ] 注册后能填写昵称、专业、年级、技能标签
- [ ] 能通过校园邮箱完成认证
- [ ] 未认证用户尝试发帖/申请时弹出认证引导
- [ ] 手机端和桌面端布局正常

- [ ] 来源徽章正确显示

### 3.4 发布页 `/publish` ★核心页面

#### 页面要素

| 区域 | 内容 | 交互 |
|------|------|------|
| 对话区 | 用户与 AI 的对话气泡 | 用户输入消息，AI 回复追问和草稿 |
| 草稿预览区 | 实时展示 AI 生成的结构化草稿 | 用户可编辑草稿字段 |
| 操作区 | "重新描述" / "确认发布" 按钮 | 确认后提交审核 |

#### 交互流程

1. 用户输入一句话描述需求（如"我想参加美赛，还缺两个队友"）
2. 前端调用 `POST /api/agent/post-draft`，传入用户输入和用户画像
3. AI 返回：
   - 追问问题（如有缺失信息）
   - 结构化草稿（活动名、人数、角色、时间、范围等）
4. 用户回答追问或直接修改草稿
5. AI 更新草稿，重复直到用户满意
6. 用户点击"确认发布"，帖子进入审核流程
7. 页面显示"发布成功，正在审核中"或"已发布"

#### 草稿字段

| 字段 | 类型 | 说明 |
|------|------|------|
| activity_name | string | 活动名称 |
| target_members | number | 目标人数 |
| needed_roles | string[] | 需要的角色 |
| weekly_hours | string | 每周投入时间 |
| school_scope | string | 组队范围 |
| deadline | string | 截止日期 |

#### 验收标准

- [ ] 用户输入一句话后，AI 在 5 秒内响应
- [ ] AI 能识别缺失字段并追问
- [ ] 草稿预览区实时更新
- [ ] 用户能手动编辑草稿任意字段
- [ ] 用户能跳过追问直接发布
- [ ] AI 调用失败时显示降级提示，允许手动填写表单
- [ ] 发布成功后跳转到帖子详情页或首页

### 3.5 帖子详情页 `/posts/:id`

#### 页面要素

| 区域 | 内容 | 交互 |
|------|------|------|
| 帖子头部 | 来源徽章 + 分类 + 标签 + 标题 | 静态展示 |
| 帖子信息 | 活动名、当前/目标人数、需要角色、截止日期、风险提示 | 静态展示 |
| 匹配推荐 | 匹配分数 + 推荐理由 + 提醒事项（如登录用户有匹配数据） | 展示 AI 匹配结果 |
| 发帖者信息 | 昵称 + 认证徽章 + 专业年级 | 点击可查看公开信息 |
| 操作区 | "申请加入"按钮（招募中）/"已满员"/"已截止" | 状态决定按钮可用性 |
| 相似帖推荐 | "类似队伍"卡片列表（P1） | 点击跳转 |

#### 验收标准

- [ ] 完整展示帖子所有字段
- [ ] 来源徽章和风险等级正确显示
- [ ] 招募中状态显示"申请加入"按钮
- [ ] 已满员/已截止状态禁用申请按钮并显示提示
- [ ] 匹配推荐区域有理由说明，不只是百分比
- [ ] 未认证用户点击申请时引导认证
- [ ] 已申请过的用户显示"已申请，等待回复"

### 3.6 消息页 `/messages`

#### 页面要素

| 区域 | 内容 | 交互 |
|------|------|------|
| 会话列表 | 对方昵称 + 最新消息 + 时间 + 未读标记 | 点击进入聊天 |
| 聊天界面 | 消息气泡（左右区分）+ 输入框 | 发送/接收消息 |
| 顶部操作 | "愿意组队"按钮 + "结束对话"按钮 | 确认组队或结束 |
| 安全提示 | 顶部固定提示"请勿在聊天中交换联系方式，确认组队后将自动解锁" | 静态展示 |

#### 验收标准

- [ ] 会话列表按最新消息排序
- [ ] 未读消息有标记
- [ ] 能发送和接收文字消息
- [ ] 消息不包含手机号、微信、QQ（被规则引擎拦截或打码）
- [ ] 顶部有安全提示
- [ ] "愿意组队"按钮双方都点击后才解锁联系方式
- [ ] "结束对话"后会话不可再发消息
- [ ] 手机端聊天界面全屏展示

## 4. 全局交互规范

### 4.1 加载状态
- 所有接口请求显示 loading 动画
- AI 生成内容时显示"AI 正在思考..."提示

### 4.2 空状态
- 列表为空时显示插画 + 引导文案
- 如"还没有帖子，去发布第一个吧"

### 4.3 错误状态
- 网络错误显示"网络异常，请稍后重试"+ 重试按钮
- AI 失败显示降级提示 + 手动操作入口

### 4.4 Toast 提示
- 操作成功：绿色 toast，2 秒自动消失
- 操作失败：红色 toast，需手动关闭
- 信息提示：蓝色 toast，3 秒自动消失
