## 1. 项目背景

大学生在参加竞赛、科研项目、课程作业等活动时，普遍面临三大痛点：

1. **信息差**：不知道有哪些活动，错过报名截止日期。
2. **需求表达不清**：不知道自己需要什么样的队友，发帖描述模糊。
3. **信任与沟通难**：不了解对方真实能力，担心信息安全，沟通效率低，成队后缺少分工和推进机制。

CampusMate AI 的核心定位是 **"AI 组队经纪人"**——不是普通论坛，而是由智能体负责理解需求、合理分类、补全信息、匹配队友、辅助沟通并推动团队真正组建的可信组队平台。

## 2. MVP 范围

### 2.1 首期支持（必须完成）

| 模块 | 说明 |
|------|------|
| 用户认证与基础资料 | 手机号/邮箱注册 + 校园邮箱校内认证，填写昵称、专业、年级、技能标签 |
| 活动/组队帖浏览 | 首页推荐、发现页分类筛选、帖子详情页 |
| AI 对话式发帖 | 用户输入一句话，AI 追问缺失信息，生成结构化帖子草稿 |
| 分类、标签和安全审核 | AI 自动分类 + 动态标签 + 规则引擎初筛 + AI 语义判断 + 风险分级 |
| 队友匹配与推荐理由 | 确定性筛选 + 语义匹配，输出匹配分数和可解释推荐理由 |
| 申请加入与临时聊天 | 申请卡片 → 发布者接受 → 平台内临时聊天 |
| 双向确认成队与联系方式解锁 | 双方点击确认 → 创建团队 → 解锁联系方式 |
| AI 生成分工与第一次会议计划 | 根据成员能力生成角色分工、会议议程、任务清单、风险提醒 |

### 2.2 暂缓项（首期不做）

- 支付、押金、复杂信用评分
- 全校官网自动抓取（首期用人工录入官方活动）
- 语音视频通话
- 完整泛生活搭子（旅游、拼团等）
- iOS/Android 原生 App（首期用响应式 Web + PWA）
- 跨校组队（首期限南京大学校内）

### 2.3 活动类型范围

**首期支持**：学科竞赛、创新创业、编程开发、数学建模、科研项目、课程作业、学习搭子、体育活动。

## 5. 核心业务规则

### 5.1 信息层级

| 层级 | 来源 | 说明 |
|------|------|------|
| 一级 | 权威信息源 | 学校官网、学院官网、大型赛事主办方网站 |
| 二级 | 认证组织 | 社团、学生组织等 |
| 三级 | 普通用户 | 发帖进入待审核区，审核后可见 |

### 5.2 分类体系

**主分类**（用户可见，少量）：
- 竞赛与项目
- 学习与科研
- 体育与健身
- 旅行与户外
- 校园生活
- 拼团与AA

**动态标签**（系统内部，精细匹配）：
- 数学建模、Python、英语写作、仙林校区、周末、新手友好、线下 等

**结构化条件**：
- 时间、地点、人数、所需能力、截止日期、风险等级、招募状态

### 5.3 安全与隐私规则

| 规则 | 说明 |
|------|------|
| 联系方式保护 | 公开帖不显示手机号、QQ、微信；双向确认后才允许交换 |
| 内容审核 | 规则初筛（身份证号、手机号、违禁词、精确住址）+ AI 语义判断 + 高风险人工审核 + 用户申诉 |
| 风险分级 | 线下、金钱、长途、夜间等场景给出额外提示 |
| 最小必要 | 不长期保存敏感证明材料，只保存认证结果 |
| Coze 边界 | 用户密码、原始身份证明、脱敏前联系方式不发送给 Coze |

### 5.4 AI 决策边界

> Coze 输出不能直接决定封禁、发布或联系方式解锁；最终决策由系统规则和用户确认完成。

## 7. 系统架构边界

```
Windows / 手机端（响应式 Web）
        ↓
自有后端 API
  ├── 用户、帖子、申请、聊天、成队、权限
  ├── 数据库
  └── Coze 工作流
        ├── 发布需求（自然语言 → 结构化草稿 + 追问）
        ├── 分类与审核（分类 + 标签 + 风险 + 修改建议）
        ├── 智能匹配（匹配分数 + 推荐理由）
        ├── 官方信息处理（官方页面 → 标准活动卡）
        └── 成队规划（分工 + 会议议程 + 任务清单 + 风险提醒）
```

**关键约束**：
- 客户端只调用自有后端，不直接访问 Coze
- Coze Token 只放在后端 `.env`
- 前端不持有任何 Token

## 8. 验收清单（最小可演示闭环）

提交前至少保证以下 10 项全部通过：

1. [ ] 一个新用户能登录并填写基础信息
2. [ ] 用户能用一句话触发 AI 发帖助手
3. [ ] AI 能生成结构化帖子草稿并追问缺失信息
4. [ ] 帖子能发布、浏览、查看详情
5. [ ] 系统能给帖子打分类、标签和风险提示
6. [ ] 用户能申请加入队伍
7. [ ] 发布者能接受申请并进入临时聊天
8. [ ] 双方确认后创建团队并解锁联系方式
9. [ ] AI 能生成分工和第一次会议计划
10. [ ] 演示数据能在 3 分钟内讲完完整故事
