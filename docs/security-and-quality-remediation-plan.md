# 梧桐遇 CampusMeet 安全与质量整改方案

更新日期：2026-09-20

## 1. 本轮目标

本轮优先处理会直接影响账号安全、线上可用性、主要操作路径和移动端体验的问题。原则是先封闭高风险入口，再处理导航、发布反馈和加载性能；涉及认证架构或存储架构的大改独立排期，避免在比赛交付前引入不可控回归。

## 2. 本轮已经实施

### 2.1 账号与接口安全

- 验证码服务未配置时默认失败，不再把验证码返回给客户端；只有显式测试模式允许返回测试码。
- 仅在 `TRUST_PROXY_HEADERS=true` 时读取代理转发地址，避免伪造来源绕过限流。
- 登录、注册、验证码和 AI 调用均有独立频率控制；登录错误统一为“账号或密码错误”。
- JWT 不再使用仓库内固定默认密钥；缺失、过短或已知默认值会拒绝签发令牌。
- 密码摘要使用常量时间比较。
- 生产环境关闭 Swagger、ReDoc 和 OpenAPI 匿名入口。
- 公共帖子列表页码和单页数量在 API 与查询层双重限制。
- AI 结构化上下文限制总字节数、嵌套深度、字段数和技能列表长度。
- 运行时 `/run`、`/stream_run`、`/node_run` 日志不再记录完整请求正文。
- 团队普通成员只能更新分配给自己的任务；任务编辑、删除和排序由队长管理。

### 2.2 前端体验与可访问性

- 增加品牌化错误页和未知路由恢复入口，不再暴露 React Router 默认错误栈。
- 探索卡片保留整卡键盘访问，同时提供明确的详情操作。
- 个人菜单使用“我的组队与发布”，直接对应发布和团队管理场景。
- 发布过程显示校验、创建、长耗时三个阶段和已用时间，并在提交期间防止重复点击、提示离开风险、保留草稿。
- 注册页增加用户协议、隐私政策入口和主动同意勾选；设置页增加数据导出与账号删除申请入口。
- 恢复浏览器缩放，调整登录页对比度，移除约 4.77 MB 的远程中文字体资源。
- 页面按路由延迟加载，入口脚本从 704.69 KB 降至 449.07 KB，gzip 从 217.29 KB 降至 149.66 KB。
- 增加 `robots.txt`、`sitemap.xml` 和 `.well-known/security.txt`。

### 2.3 部署与缓存

- API 响应增加 HSTS、CSP、`X-Frame-Options`、`X-Content-Type-Options`、`Referrer-Policy` 和 `Permissions-Policy`。
- Render 静态站点增加前端安全响应头。
- 带内容哈希的 `/assets/*` 使用一年不可变缓存，减少重复下载和回源校验。
- 运营接口路径统一为后端真实的 `/api/operators/*`。

## 3. Render 配置影响

- 现有服务需要确认 `TRUST_PROXY_HEADERS=true`。Blueprint 已包含该变量。
- `JWT_SECRET` 必须至少 32 个随机字符；Blueprint 已使用 `generateValue: true`，现有服务也必须保留该变量。
- `ABUSE_HASH_SECRET` 建议独立随机生成；Blueprint 已使用 `generateValue: true`。
- 本轮没有新增需要人工填写的第三方 Token。
- 静态站点需同步最新 Blueprint，安全响应头和长期缓存规则才会在线上生效。

## 4. 独立排期项目

以下项目需要数据库、认证协议、对象存储或托管架构联动，不在本轮直接切换：

1. 将浏览器令牌从本地存储迁移到 HttpOnly、Secure、SameSite Cookie，并配套 CSRF 防护。
2. 上传文件增加服务端字节上限、魔数识别、孤儿对象自动清理和认证材料访问审计。
3. 对 Coze 提示词做系统化不可信数据分隔、输出约束与注入对抗测试。
4. 将生产日志中的邮箱等标识统一改为不可逆指纹，并清理数据库错误中的连接字符串。
5. 解决 Render SPA rewrite 造成的 HTTP soft-404；需要边缘函数、反向代理或支持状态码回退的托管方案。
6. 迁移和验证暗色模式；它属于体验增强，不应与安全修复捆绑上线。
7. 为正式活动、上传、匹配和组队转化建立匿名化业务指标，验证 AI 相比普通筛选的真实增益。

## 5. 上线顺序

1. 合并并部署 API，确认 `/health` 正常、`/docs` 为 404、登录和验证码流程正常。
2. 同步 Render Blueprint 环境变量与静态站点响应头。
3. 部署 Web，检查首页、探索、详情、发布、消息、我的组队与发布、设置七条主路径。
4. 使用两个测试账号验证申请、双向确认、成队、任务权限和消息增量刷新。
5. 观察 24 小时登录失败、AI 配额和 429 日志，再决定是否调整阈值。

## 6. 回归标准

- 后端：完整 pytest 通过。
- 前端：完整 Vitest、TypeScript 编译和 Vite 生产构建通过。
- 部署：Render Blueprint 可解析，生产构建无大于 500 KB 的入口包警告。
- 安全：缺少邮件服务或 JWT 密钥时失败关闭；请求正文和验证码不进入普通响应或日志。
